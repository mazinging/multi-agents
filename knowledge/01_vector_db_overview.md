# 向量数据库选型总览

向量数据库（Vector Database）是专门用于存储和检索高维向量的数据库系统。在检索增强生成（RAG）场景中，它的核心职责是：把文档切块后向量化存入索引，查询时快速找出与问题语义最相近的若干个块。

## 为什么不能直接用传统数据库

传统关系型数据库的索引（B+ 树）擅长精确匹配和范围查询，比如"找出年龄大于 30 的记录"。但向量检索要回答的是"找出与这个向量最接近的 10 个向量"，这是一个高维空间中的最近邻问题。在 768 维空间里，数据点极其稀疏，B+ 树这类基于一维排序的索引完全失效。

因此向量数据库的核心是一套近似最近邻（ANN, Approximate Nearest Neighbor）算法。它不保证找到真正的最近邻，而是以很小的精度损失换取几个数量级的速度提升。

## 主流 ANN 索引算法

**HNSW（分层可导航小世界图）** 是目前最主流的索引结构。它构建一个多层图：底层包含全部节点，越往上节点越稀疏，形成类似"高速公路"的快速跳转通道。检索时从顶层开始贪心搜索，逐层下降到底层精搜。优点是查询速度快、召回率高；缺点是内存占用大（图结构本身要占空间），且构建索引较慢。

**IVF（倒排文件索引）** 先用 K-means 把所有向量聚成若干簇，检索时只查距离查询向量最近的几个簇。优点是内存占用小、构建快；缺点是召回率对聚类质量敏感，如果真实答案落在没被选中的簇里就会漏掉。通常配合 PQ（乘积量化）使用，即 IVF-PQ 组合，可以大幅压缩内存但进一步损失精度。

**暴力检索（Flat）** 不建任何索引，逐个计算相似度。精度是 100%，小规模数据（十万条以内）下速度也完全可以接受。很多团队过早引入 HNSW，其实在这个量级下 Flat 更简单也更准。

## 选型的关键维度

**数据规模** 是最重要的决策依据。一万条以下向量，Flat 暴力检索的性能绰绰有余，没必要引入复杂索引。十万到一千万条，HNSW 是主流选择。超过一亿条，需要考虑分片、IVF-PQ 或专门的分布式方案。

**成本** 方面，向量数据库的内存开销往往被低估。一条 768 维的 float32 向量占 3KB，一千万条就是 30GB 纯向量数据，加上 HNSW 图结构的额外开销，实际需要 60GB 以上内存。用 float16 或 PQ 量化能显著降低，但会损失精度。

**运维复杂度** 差异巨大。Pgvector 作为 PostgreSQL 的扩展，可以直接复用现有的数据库运维体系、备份策略和监控，团队几乎零学习成本。而 Milvus 是独立部署的分布式系统，需要理解 etcd、MinIO、Pulsar 等多个组件的协作，通常需要专职人员维护。

**中文语义支持** 不取决于向量数据库本身，而取决于你选用的 Embedding 模型。数据库只负责存和查，语义理解完全由 embedding 决定。这是初学者最常见的误解之一。中文场景应选择在中文语料上训练过的 embedding 模型，如 BGE 系列、M3E、GTE 等。

## 常见方案速览

**Pgvector** 是 PostgreSQL 扩展，支持 HNSW 和 IVF 索引，用 SQL 就能查询。适合已有 PostgreSQL 的团队、数据量在百万级以内、希望降低运维复杂度的场景。它的过滤查询（结合 WHERE 条件）能力是所有方案中最强的，因为可以直接复用 PostgreSQL 的查询优化器。

**Milvus** 是开源分布式向量数据库，功能最完整，支持多种索引类型、标量过滤、多向量检索。适合数据量巨大、需要水平扩展的场景，但部署和运维门槛最高。

**Qdrant** 用 Rust 编写，单机性能优秀，提供友好的过滤 DSL 和丰富的 payload 索引。部署比 Milvus 简单很多，适合中小团队。

**Chroma** 定位是轻量级嵌入式向量库，几行代码就能跑起来，非常适合原型验证和学习。但生产环境的高可用、持久化、并发能力较弱。

**FAISS** 是 Meta 开源的向量检索库而非数据库。它只提供索引和检索能力，不含数据持久化、权限、并发控制，需要自己封装成服务。性能是所有方案中最强的，适合追求极致性能且有能力自研的团队。

## 一个务实的决策建议

选型的常见误区是"一步到位上最先进的方案"。更务实的路径是：先用最简单能满足当前需求的方案上线（通常是 Pgvector 或 Chroma），把 RAG 的其他环节（切块策略、embedding 质量、prompt 设计）打磨好。因为实践表明，RAG 系统的效果瓶颈绝大多数时候出现在切块和 embedding 环节，而不是向量数据库的检索速度上。等数据量真正涨到索引撑不住时，向量检索层是相对容易替换的一层，因为它的接口很标准：存向量、查最近邻。
